# Public launch checklist

## Repository setup

- Create a public repository named `kepenk`.
- Keep `main` protected after the first push.
- Enable Issues, Discussions, Security Advisories, and Dependabot alerts.
- Add repository topics: `ai-agents`, `codex`, `guardrails`, `policy-engine`, `security`, `audit-log`, `developer-tools`.
- Add a concise description: `Deterministic approval and audit gate for AI coding agents.`
- Do not copy proprietary Ustaca source code, customer data, secrets, or internal logs.

## First release

- Run all tests on Linux and macOS.
- Confirm the package name is available on PyPI before publishing.
- Replace placeholder repository URLs if the final repository name changes.
- Tag `v0.1.0` and publish release notes.
- Publish the package and verify installation in a clean environment.

## Adoption work

- Add 10 real policy examples.
- Publish a 60-second terminal demo.
- Add a Codex integration guide.
- Open 5 well-scoped `good first issue` tasks.
- Ask outside developers to test it and report concrete problems.
- Respond to issues and review contributions publicly.

## Application timing

Apply when the repository demonstrates active maintenance and external value. Record actual metrics and never inflate stars, downloads, users, contributors, or security claims.
