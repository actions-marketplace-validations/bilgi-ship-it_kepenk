# Kepenk v0.2.0

**Release date:** 2026-07-31

Kepenk v0.2.0 turns the first deterministic local gate into an integration-ready open-source toolkit. The release adds versioned agent communication, reviewed policy packs, reproducible safety evidence, commit-time validation, a local MCP adapter, and an explicit pre-1.0 compatibility contract.

## Highlights

- **Versioned JSONL protocol:** long-running agents can send structured actions over stdin and receive one decision envelope per line.
- **Ten policy packs:** conservative starting rules for Python, Git, Docker, npm, PyPI, Terraform, database migrations, filesystem cleanup, repository inspection, and CI/CD releases.
- **Reproducible safety demos:** executable evidence that safe tests run, pushes pause for approval, destructive deletion is denied, audit chains verify, and publishing steps stay blocked.
- **pre-commit integration:** repositories can reject missing, malformed, or unsupported Kepenk policies before changes reach CI.
- **Local MCP policy gate:** the optional `kepenk-mcp` server exposes one read-only `kepenk_check_action` tool over stdio and never executes the proposed action.
- **v0.x compatibility contract:** stable, experimental, and internal integration surfaces are separated and protected by regression tests.

## Install from the GitHub release

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install \
  "https://github.com/bilgi-ship-it/kepenk/releases/download/v0.2.0/kepenk_gate-0.2.0-py3-none-any.whl"

kepenk --help
kepenk init
kepenk validate
```

On Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Public PyPI publication is separate and is not required to use the attached verified wheel or source distribution.

## JSONL agent protocol

```bash
printf '%s\n' \
  '{"version":1,"id":"check-1","action":{"type":"shell","command":"git status"}}' \
  | kepenk protocol
```

The response includes `version`, `id`, `ok`, and either a deterministic `decision` or structured `error`. Invalid JSON, invalid requests, and evaluation failures have stable fail-closed error codes.

## Policy packs

```bash
cp examples/policies/python-development.yaml kepenk.yaml
kepenk validate
kepenk check --action shell --command "python -m pytest"
```

Every committed pack is validated through the real CLI and covered by representative allow, approval, and deny tests.

## pre-commit hook

```yaml
repos:
  - repo: https://github.com/bilgi-ship-it/kepenk
    rev: v0.2.0
    hooks:
      - id: kepenk-validate
        files: '^(kepenk\.yaml|config/agent-policy\.yaml)$'
```

Then run:

```bash
python -m pip install pre-commit
pre-commit install
pre-commit run kepenk-validate --all-files
```

## MCP policy gate

Install the optional MCP dependencies:

```bash
python -m pip install \
  "kepenk-gate[mcp] @ https://github.com/bilgi-ship-it/kepenk/archive/refs/tags/v0.2.0.zip"
kepenk-mcp --policy /absolute/path/to/kepenk.yaml
```

The MCP host must enforce the returned decision. It should continue only for `allow`, pause for explicit human control on `approval`, and stop for `deny`, structured errors, timeouts, or transport failures.

## Compatibility

The v0.x contract stabilizes policy format v1, documented CLI commands and exit codes, JSON decision fields, JSONL protocol v1, GitHub Action inputs and outputs, and the pre-commit hook identity. The MCP adapter is intentionally marked experimental during v0.2.x rather than being presented as a v1.0 guarantee.

Normal incompatible changes require public deprecation, release notes, migration guidance, and an overlap period when technically and securely practical.

## Security boundary

Kepenk is an approval and policy layer, not a sandbox. Combine it with operating-system isolation, least-privilege credentials, protected branches, isolated runners, and normal software supply-chain controls.

The MCP adapter and JSONL protocol evaluate actions and write decisions to the audit chain; they do not execute the proposed action.
