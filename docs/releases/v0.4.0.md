# Kepenk v0.4.0

Kepenk v0.4.0 adds telemetry-free, machine-validatable public adoption evidence and strengthens the contributor and application-evidence workflow.

Kepenk remains early alpha and pre-1.0. It is a policy and approval layer rather than a sandbox, identity provider, hosted security service, or adoption-certification system.

## Highlights

### Offline adoption-evidence manifests

A public repository can record one Kepenk integration in a strict version-1 JSON manifest and validate it locally:

```bash
kepenk validate-adoption --evidence .kepenk/adoption.json
```

Machine-readable output is available with `--json`.

The validator requires:

- explicit classification as `independent_adopter` or `founding_team_pilot`;
- a public owner/name-style repository slug and matching HTTPS URL;
- a public maintainer handle, profile URL, and literal consent;
- a supported integration type;
- a tagged Kepenk semantic version;
- a public evidence URL inside the declared repository;
- a valid verification date.

Unknown fields, duplicate JSON keys, missing consent, malformed versions or dates, oversized or non-UTF-8 files, private or local hosts, URL credentials, query strings, fragments, and repository/evidence mismatches fail closed with exit code `64`.

The command performs no network request, URL fetch, telemetry, or automatic counting. Structural validity does not prove repository ownership, maintainer identity, URL availability, production security, or independent adoption. Registry inclusion still requires human review and maintainer consent.

The format is documented in `docs/adoption-evidence.md`, with a JSON Schema and public Ustaca AI founding-team example.

### Reproducible public evidence

The release includes:

- a reproducible Ustaca AI founding-team case study;
- direct links to the public policy, test suite, workflow, pull request, and successful CI run;
- a public evidence snapshot that separates founding-team pilots, independent adopters, and outside contributors;
- an adopter registry and submission template.

The current truthful record remains one founding-team pilot, zero verified independent adopters, and zero recorded outside contributors.

### Contributor onboarding

A ten-minute contributor quickstart now provides:

- development-environment setup;
- baseline verification commands;
- focused first-change examples;
- draft pull-request guidance;
- visible `good first issue`, `help wanted`, and independent-adopter paths.

GitLab CI, Azure Pipelines, and OpenTelemetry work remain open for genuine outside contribution.

### Open-source application evidence

The repository contains a form-ready Codex for Open Source application package with:

- evidence tied to public repository state;
- 500-character form-answer checks;
- explicit separation of public and private fields;
- no committed applicant email, OpenAI Organization ID, credentials, billing data, or API keys.

Submitting an application remains a private maintainer action and does not imply selection, credits, sponsorship, certification, or endorsement.

## Existing maintainer workflows

Kepenk v0.4.0 retains the v0.3 capabilities:

- declarative policy regression suites;
- explicit repository-scoped policy context;
- privacy-safe SARIF export;
- Ed25519-signed approval receipts;
- CLI, JSONL, GitHub Action, pre-commit, and MCP integration surfaces;
- hash-chained local audit records;
- ten starting policy packs and reproducible safety demonstrations.

## Compatibility

The adoption-evidence manifest and `validate-adoption` command are experimental during the v0.4 line. Patch releases will not silently reinterpret existing fields, accept `maintainer_consent: false`, or weaken the documented local/private URL rejection. A breaking format change requires a new integer manifest version and migration guidance.

Existing policy, CLI, JSONL, GitHub Action, pre-commit, MCP, SARIF, and receipt behavior remains covered by the v0.x compatibility contract.

## Security and privacy notes

- No adoption telemetry or hosted service was introduced.
- The validator never contacts declared URLs.
- A valid manifest is not repository attestation, identity proof, security certification, or automatic registry approval.
- Founding-team usage remains separate from independent adoption.
- Sensitive account and application data stays outside the public repository.
- Kepenk must still be combined with least-privilege credentials, protected branches, isolated runners, review, and operating-system controls.

## Install

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install \
  "https://github.com/bilgi-ship-it/kepenk/archive/refs/tags/v0.4.0.zip"
kepenk --help
kepenk validate-adoption --help
```

On Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```
