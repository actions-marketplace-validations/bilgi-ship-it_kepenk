# Kepenk v0.3.0

Kepenk v0.3.0 completes the maintainer-workflow milestone with deterministic policy regression tests, explicit repository context, privacy-safe SARIF reporting, and Ed25519-signed approval receipts.

Kepenk remains early alpha and pre-1.0. It is a policy and approval layer rather than a sandbox or identity system.

## Highlights

### Declarative policy tests

`kepenk test` runs a versioned YAML suite of representative actions and compares each decision with the expected effect and rule ID. Test actions are evaluated only; they are never executed and are not appended to the production audit chain.

```bash
kepenk --policy kepenk.yaml test --tests kepenk.tests.yaml
```

### Repository-scoped policy context

Structured actions may include an explicit `repository` value. Policies may match it with `repository_glob` across CLI, JSONL, the GitHub Action, MCP, and policy test suites.

Kepenk never discovers this value from the current directory, Git remotes, package metadata, or a hosting provider. It is caller-provided policy context, not authentication.

### SARIF audit export

`kepenk export-sarif` verifies the complete audit hash chain and creates deterministic SARIF 2.1.0.

- deny decisions become error results;
- approval decisions are optional warnings;
- allow decisions are omitted;
- command text, host, repository, metadata, timestamps, hashes, and unsafe paths are redacted.

```bash
kepenk --policy kepenk.yaml export-sarif \
  --audit .kepenk/audit.jsonl \
  --output reports/kepenk.sarif \
  --include-approval
```

### Ed25519 approval receipts

Kepenk can generate an Ed25519 key pair, create a signed receipt for one current `approval` decision, and verify it locally.

A receipt binds:

- the exact structured action;
- the current effect, reason, and rule ID;
- a semantic SHA-256 digest of the policy;
- the Ed25519 key ID;
- a required nonce;
- issuance and expiry timestamps.

Receipt commands never execute the proposed action. Creation refuses current `allow` and `deny` decisions. Verification reevaluates the current policy and cannot override a deny decision. One-time consumption remains the responsibility of the integrating system.

### Adoption and maintenance evidence

The repository now includes:

- a five-step adoption guide;
- a consent-based public adopter registry;
- separate founding-team and independent-adopter sections;
- case-study and adopter PR templates;
- public maintainer response targets, triage practice, review expectations, and release cadence;
- intentionally scoped outside-contributor issues.

No independent-adoption, contributor, download, or usage totals are claimed without verifiable evidence.

## Compatibility

The stable v0.x surfaces remain documented in `docs/compatibility-v0.md`. Policy v1 receives the additive `repository_glob` matcher. Existing actions that omit `repository` continue to work; a repository matcher simply does not match when context is absent.

Policy test suites, SARIF export, signed approval receipts, and the MCP adapter remain explicitly experimental during the v0.x line, with their current contracts and migration rules documented.

## Security notes

- Kepenk remains fail closed for malformed policy, protocol, audit, SARIF, key, and receipt inputs.
- Repository context does not attest repository identity.
- SARIF is a redacted reporting transformation and not the source audit record.
- A receipt proves possession of the configured private key for the signed payload, not legal identity or human review.
- Private keys must stay outside version control and should be protected with restricted access and rotation procedures.
- Kepenk must be combined with least-privilege credentials, protected branches, isolated runners, and operating-system controls.

## Install

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install \
  "https://github.com/bilgi-ship-it/kepenk/archive/refs/tags/v0.3.0.zip"
kepenk --help
```

On Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```
